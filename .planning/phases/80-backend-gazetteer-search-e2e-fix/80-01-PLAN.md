# Phase 80 / Plan 01 — Gazetteer Search: Kota / Desa / Titik End-to-End Fix

**Goal:** typing a city, kecamatan, desa, or arbitrary point into map search must produce a **relevance-correct, de-duplicated** result set from the live backend — or an explicit empty/loading/error state. It must never show a stale list, a fabricated Medan coordinate, or a spinner that never resolves because the client is pointed at a dead backend.

**Scope:** `frontend/lib/baseUrl.ts` (new), `frontend/lib/api.ts`, `frontend/components/map/CrisisMap.tsx`, `frontend/components/fleet/FleetOnboardingModal.tsx`, `frontend/app/api/proxy/[...path]/route.ts`, `frontend/.env.example`, `backend/app/routers/geocode_router.py`, `backend/tests/test_geocode_search.py` (new).

**Status:** code complete in the working tree, **uncommitted**, and **not deployed**. See §7 and 80-02 §5.

## 2. Observed failure chain (pre-fix)

| # | Layer | Pre-fix behavior | Why it looked like "search is broken" |
|---|---|---|---|
| 1 | Base-URL resolution | `getBaseUrl()` in `api.ts` returned `NEXT_PUBLIC_API_URL` **verbatim** whenever it did not contain `prehub-backend.onrender.com`; the proxy route used `x-target-base-url \|\| process.env.NEXT_PUBLIC_API_URL` with only a substring rewrite; `FleetOnboardingModal` read `process.env.NEXT_PUBLIC_API_URL` **directly** | Three separate resolvers, one of them not a resolver at all. A trailing slash (`https://host/`) produced `https://host//api/v1/geocode/search` → 404; a decommissioned host produced CORS/404. Same env value, three different outcomes |
| 2 | Client timeout | `api.geocode.search` called `request()` with no signal and no deadline | On a 77 s cold boot the `fetch` outlives the user's attention; the dropdown spinner never resolves and no error is ever rendered |
| 3 | Backend ranking | `if q_lower in slug or slug in q_lower` appended matches in **dict iteration order**, then `break` at `limit` | `q=padang` returned Padang Sidempuan / Padang Lawas / Padang Lawas Utara **before** Kota Padang. Correct data, wrong order |
| 4 | Duplicate aliases | No de-duplication | `padangsidimpuan` and `padang sidempuan` are two gazetteer keys at the **same coordinates**, so both were returned |
| 5 | Missing coordinates | `/geocode/nodes` defaulted `coords` to `(3.5952, 98.6722)` (Medan centroid) | Any node lacking coords was silently placed in Medan — a fabricated answer indistinguishable from a real one |
| 6 | Result type | Every gazetteer hit was typed `regency_hub`; the UI's badge fallback was `'Desa'` | A port or a kabupaten could be labelled "Desa"; the type carried no information |
| 7 | Cache | Empty result lists were written to the in-memory cache; Redis keys unnamespaced (`lrip:geocode:search:`) | A transient Nominatim failure during boot pinned "no results" for the process lifetime |

**Diagnosis:** layers 1–2 remove *feedback*, layers 3–6 corrupt *content*. Fixing only the backend still leaves a dead-looking UI on a cold instance; fixing only the client still shows Padang Sidempuan first.

## 3. Non-negotiable constraints

1. **Backend-first gazetteer.** `PAN_SUMATRA_GAZETTEER` is consulted before any external call. Nominatim is a *supplement* for desa/kelurahan/nagari, never the primary source for kota/hub.
2. **Never a Medan fallback.** No centroid, no province centre, no "nearest known hub" substitution. A miss is `results: []`.
3. **Honest states only.** Loading, empty, and error are three distinct, visible UI states. A partial list may be shown **only** with a label saying the live lookup failed.
4. **No silent stale data.** A response for query *N* must never populate the dropdown for query *N+1*, and clearing the box must cancel in-flight work.
5. **One resolver.** Every browser/server path resolves the backend through `getBaseUrl()`; no call site reads `NEXT_PUBLIC_API_URL` directly.

## 4. Fix design

### 4.1 One canonical base-URL resolver — `frontend/lib/baseUrl.ts` (new)

- `PRODUCTION_API_BASE_URL = 'https://peta-nadi.onrender.com'` (line 11).
- `DEAD_API_HOSTS = ['prehub-backend.onrender.com']` (line 14) — rejected, never rewritten silently at the call site.
- `sanitizeBaseUrl(raw)` (line 25) returns `string | null`:
  - trims whitespace; strips one layer of pasted `"`/`'` quotes;
  - accepts `http(s)://…` or a scheme-less `host[:port][/path]`, prepending `https://`;
  - rejects relative paths, `//host`, and non-http(s) schemes;
  - rejects dead hosts;
  - **strips trailing slashes** via `parsed.pathname.replace(/\/+$/, '')`.
- `getBaseUrl()` (line 60): env → sanitized env; else on a non-localhost browser origin → `PRODUCTION_API_BASE_URL`; else `http://localhost:8000`.
- `sanitizeWsUrl` / `getWsBaseUrl` (lines 93, 139) apply the same rules to `NEXT_PUBLIC_WS_URL`, and reject a `localhost` override outside local development.

`sanitizeBaseUrl` and `getBaseUrl` are re-exported from `api.ts` lines 1–7 so existing `import { getBaseUrl } from '@/lib/api'` call sites keep working (`useCrisisSimulationStream`, `AgentStatusWidget`, `useFleetVehicles`).

### 4.2 Call-site migration

| Site | Change |
|---|---|
| `frontend/lib/api.ts` `request()` | `getBaseUrl()` only; keeps `signal`; **never proxy-falls-back after an abort** (lines 48–52) because a fallback would restart cancelled work |
| `frontend/app/api/proxy/[...path]/route.ts` | `sanitizeBaseUrl(header) \|\| sanitizeBaseUrl(env) \|\| (production ? PRODUCTION : localhost)`; the `prehub-backend` substring rewrite is deleted |
| `frontend/components/fleet/FleetOnboardingModal.tsx` | `const apiBase = getBaseUrl()` (line 149) replaces the direct `process.env.NEXT_PUBLIC_API_URL` read, so the webhook URL shown to dispatchers is the real backend |
| `frontend/.env.example` | Documents "no trailing slash", https outside localhost, canonical production value, and that the client sanitizes/rejects the dead host |

### 4.3 Client deadline — `api.geocode.search(q, signal?, timeoutMs = 20000)`

`frontend/lib/api.ts` lines 212–239:

- Internal `AbortController` + `setTimeout(…, 20000)`.
- Caller `signal` is forwarded, and their abort propagates one-way.
- On timeout the thrown error is a **plain `Error`**: `Pencarian backend melebihi 20 detik`. It is deliberately *not* an `AbortError`, so a caller's blanket `if (err.name === 'AbortError') return;` cannot swallow a timeout into a permanent spinner.
- `finally` clears the timer and removes the abort listener.

Callers pass their own controller: `CrisisMap` (§4.4) and `FleetOnboardingModal` both abort on effect cleanup and on query change.

### 4.4 Search relevance, de-dupe, abort — `frontend/components/map/CrisisMap.tsx`

- `scoreSearchItem` (line 117): `0` exact name/display, `1` prefix, `2` word-boundary, `3` substring, `4` fallback. Local gazetteer/hub hits and live hits are ranked **together**.
- `mergeSearchResults` (line 136): concatenates groups with a stable index, sorts by `(score, index)`, **then** de-dupes so an exact name beats a locally labelled variant (`Bukittinggi` vs `Bukittinggi (Sentra Sayur & Cabai Agam)`); `isSamePlace` requires the same (parenthesis-stripped) name **and** ≤0.05° separation (~5 km), so same-named towns in different kabupaten survive. Cap 10.
- `searchResultBadge` (line 170): badge derived from `type` (`Pelabuhan`, `Bandara`, `Kota`, `Kecamatan`, `Desa`, `Hub`, `Kota/Kab`, `Wilayah`, `Titik`) instead of the old `'Desa'` catch-all.
- `cancelPendingSearch` (line 1879): clears the debounce timer, aborts the in-flight controller, and bumps `searchSeqRef`. Called before every new query, on clear, and on unmount.
- `handleSearchChange` (line 1893): local hits render immediately; a 280 ms debounce then calls the live search; the response is applied only when `seq === searchSeqRef.current`; on failure the local hits **stay** and `searchError` is set to `Pencarian live gagal (…) — menampilkan hasil gazetteer lokal saja.` (line 1951).
- Dropdown (line 2072): renders when there are results **or** `isSearching` **or** `searchError`; shows a loading row, an error row with **Coba lagi**, and an explicit empty row `Tidak ada hasil untuk “…”`.

### 4.5 Backend correctness — `backend/app/routers/geocode_router.py`

- **Ranking** — `_normalize_query` (line 62) lowercases, collapses whitespace, and strips admin prefixes (`kecamatan/kec./kelurahan/desa/gampong/nagari/pekon/kabupaten/kab./kota/kotamadya/kodya`) in a loop. `_match_score` (line 75): exact `0`, prefix `1`, word-boundary `2`, substring `3`. Candidates sort by `(score, tier, len(slug), slug)` (line ~213), so Kota Padang wins `padang` deterministically.
- **De-dupe** — a candidate within 1.5 km of an already-collected hit is skipped (~line 219), collapsing `padangsidimpuan` / `padang sidempuan`.
- **No fabricated coordinates** — `/geocode/nodes` skips a node whose `coords` is missing/invalid and logs a warning (lines 124–130); the `(3.5952, 98.6722)` default is deleted.
- **Honest type** — `_gazetteer_result_type` (line 95) maps `corridor_point` → `hub`, `kecamatan_kelurahan`/tier 1 → `kecamatan`, tier 2 → `regency`, else `hub`; `/nodes` also returns `precision_tier`.
- **Gazetteer-first skip** — when the top gazetteer score is exact (line 214), Nominatim is not called for that query (line 239). Desa/kecamatan queries still fall through to Nominatim.
- **Bounded cache** — `_remember` (line 55) caps both caches at `_IN_MEMORY_CACHE_LIMIT = 512` (line 28) by evicting the oldest inserted key.
- **No negative cache** — results are cached only `if results:` (line 300); an empty list is returned, never stored.
- **Namespace bump** — Redis keys are now `lrip:geocode:search:v2:{query}:{limit}` (read line 186, write line 305, TTL 86400), so pre-fix keys cannot be replayed.

## 7. Risks / trade-offs

- **20 s < 77 s cold start.** By design, a cold instance now produces a *visible failure* instead of an infinite spinner. It does **not** make cold search succeed. Retry-after-warm is the accepted UX until the backend stays warm.
- **A 502 from a booting instance does not trigger the proxy fallback.** `request()` only falls back on a thrown network error; an HTTP 502 throws `API … → 502` and stops (api.ts lines 48–66). The proxy would hit the same booting instance anyway, so this is a message-quality gap, not a routing gap.
- **Cross-origin search depends on preflight during boot.** The browser sends `OPTIONS` before the direct `https://peta-nadi.onrender.com` call; if Render cannot answer during boot, the browser reports a CORS error rather than a timeout. The 20 s deadline still terminates the UI state, but the message shown is the generic live-search failure.
- **Stale Redis `search:v2` keys.** A key written by an intermediate deploy persists for 86 400 s and is served with `cached: true`. v1 keys are correctly ignored, but v2 is only safe if nothing older wrote it.
- **Synchronous Redis inside async endpoints.** `r.get` / `r.set` are blocking calls with `socket_connect_timeout=5` and `retry_on_timeout=True`; if Redis is configured but unreachable, each search can block the event loop for seconds during boot.
- **`_remember` is FIFO, not LRU.** Reads do not refresh insertion order, so a hot key can be evicted while cold keys stay. Bounded memory is the goal; hit-rate optimality is not.
- **Type vocabulary is duplicated.** Backend emits `hub | kecamatan | regency`; the badge mapping lives in `CrisisMap`. Adding a backend type silently degrades to `Titik`.
- **No automated test for the frontend merge/de-dupe.** Only `tsc` covers it; behaviour is verified by inspection and manual probes.
- **`FleetOnboardingModal` is large and was reworked for other features in the same working tree.** The base-URL change is one line (149) plus geocode effects (194–252); the rest of its diff is out of scope for this phase.
