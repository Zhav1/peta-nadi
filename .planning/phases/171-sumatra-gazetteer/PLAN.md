## Objective

Make place search work offline across Sumatra. Search matched only
slugs, and the catalogue behind it was tiny — so an operator typing a
kecamatan name got nothing, and typing a near-miss got nothing either.

## Scope IN

- `backend/app/nlp/data/sumatra_admin_gazetteer.json` (new, +27,421):
  **2,096 records** — 118 kabupaten, 34 kota, 1,944 kecamatan. Built from
  wilayah.id + OpenStreetMap + Wikidata.
- `scripts/build_sumatra_gazetteer.py` (new, +1,294): reproducible
  builder for the dataset.
- `backend/app/nlp/gazetteer_data.py` (+281): loading, alias resolution,
  fuzzy and diacritic-insensitive matching.
- `backend/app/routers/geocode_router.py` (+152): search path returns
  gazetteer hits offline (~2,100 records); `desa` lookups go to
  Nominatim and degrade to an **honest offline state** rather than an
  error or a guess.
- `frontend/components/map/CrisisMap.tsx`: offline/`desa` affordance.
- Tests: `backend/tests/test_gazetteer_coverage.py` (new, 146 lines),
  `frontend/e2e/gazetteer-search.spec.ts` (new, 168 lines).

## Scope OUT

- No expansion beyond Sumatra's 10 provinces.
- No fabrication of missing coordinates — see the documented shortfall.
- No change to routing, hazard, or news paths.

## Decisions locked

1. **Honest shortfall beats false completeness.** 23 rows could not be
   placed — Natuna, Belitung Timur, and 21 kecamatan — and were **not
   fabricated**. They are absent, and the absence is recorded.
2. Offline is a state the UI states, not an error it hides. `desa`
   search needs a network provider and says so.
3. Aliases and diacritics are matching concerns, not data concerns: the
   canonical name stays clean, matching accepts the variants.
4. The dataset is generated by a script in-repo, so a rebuild is
   auditable rather than a one-off paste.
