# Plan 38-01: Operator Decision Taxonomy, Ground-Truth Outcomes Endpoints & SQLite Local Storage

<objective>
Build the core data contracts, persistence layer, and REST endpoints for closed-loop human-in-the-loop decision logging (ACCEPT, REJECT, OVERRIDE) and post-incident ground-truth outcome verification at T+12h / T+24h, backed by local SQLite storage for guaranteed offline resilience.
</objective>

   - `list_outcomes(incident_id: Optional[str] = None, horizon: Optional[str] = None, limit: int = 50) -> List[dict]`
   - `get_pending_sync_count() -> int`

<task id="38-01-02">
<read_first>
- backend/app/routers/approvals.py
- .planning/phases/38-closed-loop-operator-decision-trace-ground-truth-outcome-eng/38-CONTEXT.md
</read_first>
<action>
1. Create `backend/app/schemas/decision_schemas.py`:
   - Enum `DecisionAction`: `ACCEPT`, `REJECT`, `OVERRIDE`.
   - Enum `TacticalManeuver`: `REROUTE`, `HOLD`, `CONTINUE`.
   - Pydantic model `DecisionTraceCreate`:
     - Fields: `incident_id`, `route_id`, `action: DecisionAction = DecisionAction.ACCEPT`, `tactical_action: TacticalManeuver = TacticalManeuver.REROUTE`, `operator_id: str`, `recommended_route: Optional[Dict[str, Any]] = None`, `custom_constraints: Optional[Dict[str, Any]] = None`, `notes: Optional[str] = None`.
     - Model validator: If `action in (DecisionAction.REJECT, DecisionAction.OVERRIDE)` and not `notes`: raise `ValueError("Notes are mandatory when action is REJECT or OVERRIDE.")`.
   - Pydantic model `DecisionTraceResponse`:
     - Fields: `id`, `incident_id`, `route_id`, `action`, `tactical_action`, `operator_id`, `recommended_route`, `custom_constraints`, `notes`, `created_at`, `status`.
2. Refactor `backend/app/routers/approvals.py`:
   - Keep backward compatibility for legacy `ApprovalCreate` payload while parsing the extended fields.
   - Dual-write strategy: attempt Supabase insert; if Supabase is offline or raises error, persist immediately via `backend.app.db.local_storage.save_decision_trace` with `status: "local_queued"`.
   - Update `GET /approvals` to query Supabase, and if Supabase returns 0 or fails, pull records from `local_storage`.
</action>
<acceptance_criteria>
- `backend/app/schemas/decision_schemas.py` validates mandatory notes on `REJECT` and `OVERRIDE`.
- `POST /api/v1/approvals` accepts `action: "OVERRIDE"`, `tactical_action: "HOLD"`, and custom constraint parameters.
- Offline submissions return HTTP 201 with `status: "local_queued"`.
</acceptance_criteria>
</task>

<action>
1. Add outcome models to `backend/app/schemas/decision_schemas.py`:
   - Enum `OutcomeHorizon`: `T_12H = "T+12h"`, `T_24H = "T+24h"`.
   - Enum `VerificationSource`: `FIELD_REPORT`, `ANTARA_NEWS`, `BMKG_ALL_CLEAR`, `POLDA_TRAFFIC_POLICE`.

   - Model `OutcomeResponse` and `OutcomeListResponse`.
2. Create `backend/app/routers/outcomes_router.py`:
   - Mount router at `/outcomes` (prefixed under `/api/v1`).
   - `POST /`: Ingest verified outcome. Write to Supabase table `ground_truth_outcomes`, falling back to `local_storage.save_outcome()`.
   - `GET /`: Retrieve list of outcomes, filtered by `incident_id` or `horizon`.
3. Register `outcomes_router.py` in `backend/app/main.py` under `/api/v1`.
</action>

<threat_model>
- Threats:
  - Unauthorized tampering with operational audit logs or ground-truth outcome entries.
  - Silent data loss when cloud connectivity drops during critical field emergencies.
- Mitigations:
  - SQLite local fallback ensures atomic ACID transaction persistence on disk (`backend/data/prehub_local.db`).
  - Mandatory audit notes and explicit operator identity logging on all override and rejection decisions.
</threat_model>
