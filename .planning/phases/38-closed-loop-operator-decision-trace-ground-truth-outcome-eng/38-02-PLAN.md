<action>
Create `backend/app/services/outcome_evaluation_service.py`:
1. Define evaluation data models:
   - `VarianceMetrics`: `delay_error_hours: float`, `relative_delay_error: float`, `price_variance_pct: float`, `accuracy_score: float`.
   - `RecalibrationAdvisory`: `channel_adjustments: Dict[str, float]`, `recommended_weights: Dict[str, float]`, `learning_rate: float`, `advisory_rationale: str`.
   - `OutcomeEvaluationReport`: `incident_id: str`, `predicted_delay_hours: float`, `actual_delay_hours: float`, `predicted_price_spike_pct: float`, `actual_price_spike_pct: float`, `variance: VarianceMetrics`, `recalibration: RecalibrationAdvisory`.
2. Implement functions:
   - `compute_variance(pred_delay: float, actual_delay: float, pred_price: float, actual_price: float) -> VarianceMetrics`
   - `compute_recalibration_advisory(variance: VarianceMetrics, current_weights: Optional[Dict[str, float]] = None, learning_rate: float = 0.05) -> RecalibrationAdvisory`
   - `evaluate_incident_outcome(incident_id: str, predicted: dict, actual: dict) -> OutcomeEvaluationReport`
3. Add endpoint `GET /api/v1/outcomes/evaluation/{incident_id}` in `backend/app/routers/outcomes_router.py` to compare recorded decision traces and ground-truth outcomes.
</action>
<acceptance_criteria>
- `compute_variance` correctly computes delay and price error deltas.
- `compute_recalibration_advisory` outputs normalized weights ($\sum w_k = 1.0$) with damped step ($\eta = 0.05$).
- `GET /api/v1/outcomes/evaluation/{incident_id}` returns a complete `OutcomeEvaluationReport`.
</acceptance_criteria>
</task>
