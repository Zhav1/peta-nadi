<action>
Create directory `data/benchmark` and generate `data/benchmark/sumatra_disruptions_ground_truth.json`.
Populate the file with exactly 60 scenarios adhering to the schema defined in RESEARCH.md §1:
- 35 Positive Disruption Events: Historical and synthetic floods (Jalintim Betung, Langkat, Kampar, Musi Banyuasin), landslides (Sitinjau Lauik, Bukit Barisan Tarutung-Sibolga, Curup-Lubuklinggau), port congestion (Belawan rob, Bakauheni ASDP, Dumai Ro-Ro), road subsidence (Way Sekampung, Bengkulu coastal), and commodity supply shocks across all 8 Sumatra provinces.
- 25 Negative / Benign Controls: Routine heavy rain with working drainage, standard rush hour traffic around provincial capitals, unverified social media rumors lacking news backing, and minor sea swell not stopping ferries.
Each scenario must include: `id`, `name`, `province`, `corridor`, `coordinates`, `disaster_type`, `sensor_inputs` (BMKG alert level, Open-Meteo rain rate mm/h, TomTom delay min and speed ratio, OSINT verified headline, PIHPS price shock), and `ground_truth` (`is_disruption`, `actual_delay_hours`, `observed_price_impact_pct`, `corridor_severed`).
</action>

<action>
Implement the empirical evaluation harness in `scripts/evaluate_metrics.py`.
The script must:
1. Load `data/benchmark/sumatra_disruptions_ground_truth.json`.
2. Convert each scenario's `sensor_inputs` into simulated agent findings (`data_collection_finding`, `osint_hazard_finding`, `prediction_finding`, `route_optimization_finding`, `economic_intelligence_finding`) compatible with `compute_consensus()` in `agents.tools.consensus_gate`.
3. Evaluate each scenario through `compute_consensus()`, determining if the event is promoted to `validated`.
4. Measure evaluation latency per scenario in milliseconds.
5. Compute the empirical confusion matrix (True Positives, False Positives, True Negatives, False Negatives).
6. Calculate Precision, Recall, F1-Score, and False Positive Rate (FPR).
7. Format and print a clean Markdown summary table to stdout.
8. Save results to `test-results/benchmark_evaluation_report.json` with timestamp, parameters, and full metrics.
9. Enforce gating assertions: exit with code 1 if Precision < 0.85, Recall < 0.80, or F1 < 0.82; exit 0 otherwise.
10. Support CLI arguments `--verbose` (prints each scenario decision) and `--dataset <path>`.
</action>
<acceptance_criteria>
- `scripts/evaluate_metrics.py` exists and is executable via `python scripts/evaluate_metrics.py`.
- Running the script produces a Markdown table displaying Precision, Recall, F1-Score, and FPR.
- `test-results/benchmark_evaluation_report.json` is created with valid metric keys.
- Execution exits with status code 0 when metrics satisfy the gating thresholds (Precision >= 0.85, Recall >= 0.80, F1 >= 0.82).
</acceptance_criteria>
</task>
