# Phase 79 / Plan 02 — Q3: Route Loading State + Batal (Abort)

**Goal:** while a route is computing, the operator gets persistent, honest feedback (elapsed seconds + cold-render hint) and a working **Batal** button that actually stops the work and removes its pending result. No 3-second toast pretending the request is over.

**Scope:** `frontend/components/dashboard/RoutingStatusBanner.tsx` (new), `frontend/components/dashboard/DashboardClient.tsx`, `frontend/components/dashboard/TopNavTelemetry.tsx`, `frontend/lib/api.ts`, `frontend/lib/aiDynamicRouter.ts`, `frontend/lib/mapboxRoutingService.ts`.

## 2. Design

### 2.1 `RoutingStatusBanner.tsx` (new, ~105 lines)

Two mutually exclusive states, one component:

**Loading** (`role="status"`, `aria-live="polite"`, `data-testid="routing-status-banner"`):

- Spinner (`Loader2`, animated) + `Menghitung rute...`.
- Elapsed seconds, updated every 250 ms from a `Date.now()` anchor.
- At `elapsedSeconds >= 10`, appends `— render dingin bisa 30-50 detik`.
- **Batal** button (rose, `title="Batalkan perhitungan rute yang sedang berjalan"`).

**Error** (`role="alert"`):

- `AlertTriangle` + message + dismiss `X` (`onDismissError`).

Returns `null` when `!isLoading && !error`, so it never occupies map space in the idle state. Mounted absolutely at `top-14 left-1/2 -translate-x-1/2 z-40` inside the map container (so it never collides with the top nav or the simulator bar).

### 2.2 Abort plumbing (bottom-up)

| Layer | Change |
|---|---|
| `frontend/lib/api.ts` | `request()` reads `options.signal`; passes it to `fetch`; **if aborted, rethrows instead of falling back to `/api/proxy`** (falling back would restart the cancelled work); post-await `if (signal?.aborted) throw createAbortError()`. `api.routing.optimizeRouting(payload, signal?)` takes the signal. |
| `frontend/lib/aiDynamicRouter.ts` | `throwIfAborted(signal)` at each leg boundary; `signal` threaded through `requestMapboxDirections`, `fetchMapboxRouteWithForcedWaypoint`, `fetchMapboxAlternativeDrivingRoutes`, `fetchMapboxDrivingRoute`, `calculateSeaIntermodalCorridor`, `calculateAirIntermodalCorridor`, `calculateAIDynamicDetourRoutes`. Abort is rethrown from every `catch` (never swallowed into `return null`). |
| `frontend/lib/mapboxRoutingService.ts` | `fetchMapboxDirections(..., signal?)`: pre-flight abort check, signal to `fetch`, rethrow on abort, and a post-flight abort check **before** returning `fallbackHighwayRoute`. |

**Why the abort must not be swallowed:** every one of these functions has a "be resilient" catch that degrades to an offline estimate. Without an explicit `isAbortError` branch, `Batal` would paint a straight line labeled `SIMULASI/OFFLINE` — the cancel button would *create* a corridor.

### 2.3 Request identity + staleness

In `DashboardClient`:

```
routingAbortControllerRef: AbortController | null
routingInFlightKeyRef:     string | null   // JSON of [origin, dest, modality, hazard, radius, type, tier]
routeCalculationReqIdRef:  number          // pre-existing, now actually compared
```

- New selection → `abort()` previous controller, new controller, `reqId = ++routeCalculationReqIdRef.current`.
- `isStale() = signal.aborted || routeCalculationReqIdRef.current !== reqId` — checked after **every** await and before **every** state write (`setCurrentMapRoutes`, `setRoutingInfo`, `setSelectedCrisis`).
- `finally` only clears `isRoutingLoading` / `routingAbortControllerRef` when `routeCalculationReqIdRef.current === reqId`, so a late-finishing stale request cannot clear the banner of the request that replaced it.

### 2.4 De-duplication (handler vs effect)

`handleNodeSelected` calls `updateBaselineMapboxRoute` directly, and the auto-recompute effect fires for the same selection right after state commits. Without a guard, the second call aborts the first — the click would always cancel itself.

`routingInFlightKeyRef` holds the route key; a second invocation with an identical key returns `false` immediately instead of aborting. The key includes hazard center/radius/type/tier, so a genuine change still supersedes.

### 2.5 Reset paths abort

`handleResetNodes`, `handleResetDemo`, and `handleCancelRouting` all: abort → null controller → null in-flight key → `routeCalculationReqIdRef.current++` → `setIsRoutingLoading(false)` → clear error/elapsed → clear routes (+ `setSelectedCrisis(route_recommendations: [])` in the cancel path) → stop demo "calculating" flag.

**Batal (`handleCancelRouting`)** additionally toasts `Perhitungan rute dibatalkan.` and keeps the selected endpoints (cancelling a computation is not the same as clearing the pair).

### 2.6 HUD honesty

`TopNavTelemetry` gains `isRoutingLoading?: boolean`:

- Pill: `RUTE: ...` while loading, else `compute_time_ms` or `< 15ms`.
- Popover: latency value `...` and caption `Menghitung rute...` instead of `Sub-Detik Deterministik` while loading.
- `DashboardClient` passes `routingInfo={isRoutingLoading ? null : routingInfo}` and nulls `routingInfo` at the start of every request, so a previous solver latency can never be read as belonging to the current one.

This fixes the *confusion* (never show a stale/irrelevant number during a request). It does **not** yet reconcile solver-ms vs HTTP wall time — logged in Plan 06 as `HUD ms fix`.

## 4. Known limits (deliberately out of scope)

- **The abort is client-side only.** `frontend/app/api/proxy/[...path]/route.ts` does not forward a signal to `peta-nadi.onrender.com`; the Render worker may finish the work after the browser cancels. The user-visible result is correct (no state write), but server CPU is not reclaimed.
- **Mapbox Directions fetches inside a Promise.all** stop at the next `throwIfAborted` boundary, not mid-socket, for calls already in flight.
- **No automatic retry.** A failed computation requires the operator to re-select; silent retries would restart the cold-start clock invisibly.
