# Plan 43-01: Backend Fleet Ingestion Engine, Telemetry Webhook & SQLite Persistence

**Phase:** 43
**Plan:** 43-01
**Goal:** Implement FastAPI backend endpoints for single-vehicle registration, bulk CSV/Excel manifest parsing, standard TMS GPS telematics webhook ingestion, SQLite local storage persistence, and TelemetryService dynamic fleet fusion.

---

## 1. Requirements & Invariants

- **FR-16.1**: Single-vehicle manual registration (`POST /api/v1/fleet/register`) saving vehicle metadata, driver contacts, modality, cargo, cold-chain temperature, and route paths.
- **FR-16.2**: Bulk delivery manifest parser (`POST /api/v1/fleet/upload-manifest`) parsing CSV and Excel rows with schema validation and automatic Sumatra hub coordinate resolution.
- **FR-16.3**: Standardized TMS telematics webhook endpoint (`POST /api/v1/fleet/telemetry/ingest`) processing real-time GPS pings `(lat, lon, speed, heading, temperature)` from Traccar, EasyGo, McEasy, or custom devices.
- **FR-16.4**: Dynamic fleet synchronization: `TelemetryService.get_unified_fleet()` dynamically merges user-registered vehicles with the master baseline, ensuring real-time GPS pings update map coordinates.
- **NFR-11.1 - NFR-11.3**: RBAC enforcement (Dispatcher & Guest permitted, Regulator rejected with HTTP 403 Forbidden on write operations) and SQLite local persistence fallback.

---

## 2. Technical Scope & Implementation Steps

### Task 1: Schemas (`backend/app/schemas/fleet_ingest.py`)
- Define Pydantic v2 models:
  - `SingleVehicleRegisterRequest`: `vehicle_id`, `name`, `modality` (`truck` | `maritime` | `air`), `driver_name`, `driver_phone`, `cargo`, `origin`, `destination`, `speed_kmh`, `temperature_c`, `path`, `status`.
  - `BulkManifestUploadRequest`: `vehicles: List[SingleVehicleRegisterRequest]`, `manifest_name`, `notes`.
  - `TMSVehicleTelemetryPing`: `vehicle_id`, `latitude`, `longitude`, `speed_kmh`, `heading_deg`, `altitude_m`, `temperature_c`, `timestamp`, `battery_level`, `ignition`.
  - `FleetIngestResponse`: `status`, `message`, `registered_count`, `vehicles`.
  - `ManifestTemplateResponse`: `headers: List[str]`, `sample_csv: str`.

### Task 2: SQLite Local Persistence (`backend/app/db/local_storage.py`)
- Add table `custom_fleet_vehicles`:
  ```sql
  CREATE TABLE IF NOT EXISTS custom_fleet_vehicles (
      id TEXT PRIMARY KEY,
      vehicle_id TEXT UNIQUE NOT NULL,
      name TEXT NOT NULL,
      driver_name TEXT,
      driver_phone TEXT,
      modality TEXT NOT NULL,
      cargo TEXT,
      origin TEXT,
      destination TEXT,
      speed_kmh REAL DEFAULT 60.0,
      temperature_c REAL,
      path_json TEXT,
      status TEXT DEFAULT 'moving',
      organization_id TEXT DEFAULT 'org-prehub-pilot',
      created_by TEXT DEFAULT 'dispatcher',
      sync_status TEXT DEFAULT 'pending',
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );
  ```
- Add table `fleet_telemetry_logs`:
  ```sql
  CREATE TABLE IF NOT EXISTS fleet_telemetry_logs (
      id TEXT PRIMARY KEY,
      vehicle_id TEXT NOT NULL,
      latitude REAL NOT NULL,
      longitude REAL NOT NULL,
      speed_kmh REAL DEFAULT 0.0,
      heading_deg REAL DEFAULT 0.0,
      altitude_m REAL DEFAULT 0.0,
      temperature_c REAL,
      raw_payload TEXT,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );
  ```
- Implement CRUD helper functions:
  - `save_custom_vehicle(data: Dict[str, Any], db_path: Optional[str] = None) -> Dict[str, Any]`
  - `save_batch_custom_vehicles(data_list: List[Dict[str, Any]], db_path: Optional[str] = None) -> int`
  - `list_custom_vehicles(db_path: Optional[str] = None) -> List[Dict[str, Any]]`
  - `delete_custom_vehicle(vehicle_id: str, db_path: Optional[str] = None) -> bool`
  - `log_telemetry_ping(ping: Dict[str, Any], db_path: Optional[str] = None) -> Dict[str, Any]`

### Task 3: TelemetryService Dynamic Fusion (`backend/app/services/telemetry_service.py`)
- Add custom vehicle registry state & in-memory coordinate caches.
- Update `get_unified_fleet()`:
  - Fetch custom registered vehicles from SQLite or memory.
  - Enrich custom vehicles with real-time GPS pings, bearing calculations, and cold-chain evaluation.
  - Merge seamlessly into the unified fleet array returned to clients.
- Add methods:
  - `register_custom_vehicle(vehicle_dict)`
  - `register_batch_custom_vehicles(vehicle_dicts)`
  - `ingest_gps_ping(ping_dict)`
  - `remove_custom_vehicle(vehicle_id)`

### Task 4: Ingestion REST Router (`backend/app/routers/fleet_ingest_router.py`)
- Endpoints:
  - `POST /api/v1/fleet/register` — Single vehicle registration (RBAC: Dispatcher, Guest).
  - `POST /api/v1/fleet/upload-manifest` — Upload manifest JSON or multipart CSV/Excel (RBAC: Dispatcher, Guest).
  - `POST /api/v1/fleet/telemetry/ingest` — Webhook receiver for live GPS pings.
  - `GET /api/v1/fleet/custom` — Retrieve user-registered custom fleet units.
  - `DELETE /api/v1/fleet/custom/{vehicle_id}` — Remove a custom onboarded vehicle (RBAC: Dispatcher, Guest).
  - `GET /api/v1/fleet/manifest/template` — Retrieve standard CSV template & headers.
  - `POST /api/v1/fleet/telemetry/simulate-ping` — 1-click test GPS ping generator.

### Task 5: Router Registration & Pytest Suite
- Mount `fleet_ingest_router.py` in `backend/app/main.py`.
- Write `backend/tests/test_fleet_ingest.py`:
  - Test single registration validation and SQLite storage.
  - Test bulk CSV string parsing and waypoint interpolation.
  - Test live GPS telemetry webhook ingestion and coordinate updating.
  - Test RBAC: Dispatcher allowed, Regulator denied (HTTP 403).
  - Test custom vehicle retrieval and deletion.
