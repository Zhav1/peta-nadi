# Phase 43.5 Learnings: Architectural Constraints, Environmental Realities & Diagnostics

**Phase:** 43.5  
**Milestone:** M3 - PreHub MVP Pilot Operations & Multi-Persona Dispatcher Platform  
**Date:** 2026-09-28  

---

## 1. Cloud & Serverless Deployment Realities (Render Free Tier)

### A. Cold Boot Spin-Down Latency
- **Finding:** Render's Free Web Service spins down after 15 minutes of inactivity. The initial probe to `https://peta-nadi.onrender.com/health` required **484.4 ms** when waking up, but can take **30-50 seconds** if the container was completely cold.
- **Impact on Frontend:** When the frontend makes an immediate batch of `fetch()` calls against a cold backend, browser requests can timeout or throw `TypeError: Failed to fetch`.
- **Mitigation Pattern:** The in-app diagnostic console (`SystemObservabilitySection.tsx`) uses a sequential batching mechanism (`batchSize = 4`) and displays a clear `PROBE` status while waiting, preventing browser connection pool exhaustion.

### B. Deployment Lag & Route Discrepancies
- **Finding:** In our live audit, 5 endpoints returned `404 Not Found` on `https://peta-nadi.onrender.com` even though all 108 backend tests were passing locally.
- **Forensic Diagnosis:** By fetching `/openapi.json` directly from the live Render host, we confirmed Render was running an older deployment image from Phase 42, missing `fleet_ingest_router.py` (Phase 43) and `POST /api/v1/news/verify`.
- **Takeaway:** Never assume that passing local tests means cloud deployment is in sync. Always perform a schema diff against `/openapi.json` on the remote host before diagnosing code bugs.

## 2. API Contract & Validation Constraints

### A. Pydantic Schema Required vs Optional Fields
- **Finding:** During our initial script probe, `POST /api/v1/fleet/register` returned `422 Unprocessable Entity`.
- **Root Cause:** `SingleVehicleRegisterRequest` required `name: str` alongside `vehicle_id: str`. The audit probe sent `vehicle_id` and `driver_name` but omitted `name`.
- **Takeaway:** All test probes and frontend forms must strictly mirror required Pydantic v2 model fields. When designing ingestion schemas, ensure documentation templates clearly mark mandatory vs optional keys.

### B. Route Redundancies & Legacy Deprecations
- **Finding:** Legacy endpoint `/api/v1/commodity/lag-correlation` (from Phase 17) was superseded in Phase 35 by `/api/v1/news/market-regime` and `/api/v1/commodities/prices`.
- **Takeaway:** When deprecating endpoints across roadmap milestones, update the client SDK (`frontend/lib/api.ts`) immediately to prevent dead references in the frontend.

## 3. UI/UX Design System Constraints (Strict Minimalist Operator Ergonomics)

### A. Non-AI Anti-Patterns & Boasting Elimination
- **Constraint Enforced:**
  - ❌ Zero emojis in UI buttons, tables, badges, or headers.
  - ❌ Zero boastful marketing copy (e.g. no "QUANTUM AI CLUSTER", "SUPER SPEED ENGINE").
  - ✅ 100% monochrome Lucide SVG icons (`Server`, `Radio`, `Database`, `Terminal`, `CheckCircle2`, `XCircle`).
  - ✅ High-contrast Glassmorphic styling (`backdrop-blur-md bg-[#13161c]/90 border border-white/10`).

### B. Prometheus / Grafana vs In-App Sub-Tab Tradeoff
- **Architectural Decision:** Avoided deploying standalone Prometheus + Grafana Docker containers.
- **Rationale:** External observability stacks require 1-2 GB extra RAM, separate open ports, and complex auth configurations that fail on free-tier single dyno containers. Building native React diagnostic components provides zero-overhead observability directly visible to evaluators and operators inside the browser.

---

## 4. Checklist for Subsequent Phases (Phase 44+)

1. **Verify Cloud Sync:** After completing a phase with new backend routes, ensure GitHub `main` is pushed and cloud build is complete before testing cloud targets.
2. **Batch Client Invocations:** In frontend components, avoid firing unbounded `Promise.all()` over 20+ endpoints simultaneously. Use chunked `Promise.all()` (e.g. 4-5 requests per batch).
3. **Preserve Navigation Simplicity:** Use sub-tab toggles within existing top-level views (`EVALUATION`, `ANALYTICS`, `MAP`) rather than adding top-level navigation clutter.
