# Phase 69 Research: WebGL Telemetry Stabilization & Main-Thread Performance Optimization

## 1. Executive Summary & Root Cause Findings

Empirical investigation conducted across local codebase and production live runtime (`https://pre-hub.vercel.app/dashboard?guest=1`) via Chrome DevTools MCP identified three interrelated architectural defects causing runtime crashes, visual artifacts, and severe main-thread UI latency.

---

## 2. Issue 1: `RangeError: Invalid array length` in `spatialHashArbiter.ts`

### Root Cause Mechanism:
In `frontend/lib/spatialHashArbiter.ts` (lines 126-147):
```typescript
const minCx = Math.floor((item.screenX - w / 2) / cellSize);
const maxCx = Math.floor((item.screenX + w / 2) / cellSize);
const minCy = Math.floor((item.screenY - h / 2) / cellSize);
const maxCy = Math.floor((item.screenY + h / 2) / cellSize);

let hasCollision = false;
const targetKeys: number[] = [];

for (let cx = minCx; cx <= maxCx; cx++) {
  for (let cy = minCy; cy <= maxCy; cy++) {
    const key = packCellKey(cx, cy);
    if (this.occupiedCells.has(key)) {
      hasCollision = true;
      break;
    }
    targetKeys.push(key); // <-- Line 144
  }
  if (hasCollision) break;
}
```

When `map.project(finalPos)` projects coordinates behind the camera horizon, during high camera pitch/tilt, or when `finalPos` has extreme/unbounded dead-reckoning drift, `screenPt` can evaluate to `Infinity` or `-Infinity`.
In JavaScript V8:
- When `minCy = -Infinity` and `maxCy = Infinity`:
- Iteration starts with `cy = -Infinity`.
- Evaluates `cy <= maxCy` as `true` (`-Infinity <= Infinity`).
- Evaluates `cy++` as `-Infinity + 1 === -Infinity`. `cy` never increments!
- The loop becomes an infinite loop executing `targetKeys.push(key)` millions of times until V8 exceeds its internal dense array limit ($2^{32} - 1$), throwing `RangeError: Invalid array length`.

### Empirical Proof:
Tested in Node.js runtime:
```javascript
let arr = [];
for (let i = -Infinity; i <= Infinity; i++) {
  arr.push(1);
}
// Throws: RangeError: Invalid array length
```

### Remediation Strategy:
1. Viewport & Finite Guard:
   ```typescript
   if (!Number.isFinite(item.screenX) || !Number.isFinite(item.screenY)) return;
   if (item.screenX < -200 || item.screenX > 3000 || item.screenY < -200 || item.screenY > 3000) return;
   ```
2. Dimension Clamping:
   Clamp `minCx`, `maxCx`, `minCy`, `maxCy` to a maximum allowable cell span (e.g., maximum 6x4 cells = 24 cells). If `(maxCx - minCx + 1) * (maxCy - minCy + 1) > 24`, skip candidate or clamp bounds.

## 3. Issue 2: Mystery Purple & Green Needles Disappearing on Zoom-In

### Layer Identification:
- The lines are generated by Deck.gl `PathLayer` with ID `deck-fleet-vectors` in `frontend/components/map/FleetVehicleLayer.tsx` (lines 571-592):
  - `v.modality === 'air'`: color `[192, 132, 252, 200]` (Light Purple / Violet).
  - `v.modality === 'land'`: color `[52, 211, 153, 200]` (Emerald Green).
- The vectors project forward along the vehicle's `finalBearing` for a fixed geodesic distance:
  `distanceKm = Math.max(0.5, speedKmh * scaleHours)` (41.6 km for air, 3.0 km for trucks).

### Why They Look Like Random Needles Pointing Straight North:
1. In `frontend/hooks/useFleetVehicles.ts`, fallback aircraft (`AIR-001` through `AIR-005`) lack `heading_deg` or `cog_deg` properties.
2. In `FleetVehicleLayer.tsx`: `effectiveBearing = v.cog_deg ?? v.heading_deg ?? (v as any).bearing ?? 0;` falls back to `0`.
3. 0° on a geographic compass is **Due North**.
4. The system projects a 41.6 km line due North from every plane, appearing as a vertical needle with no label or context.

### Why They Disappear on Zoom-In:
1. **Frustum Culling**: At macro overview (zoom 5-6), all of Sumatra is on screen. When zooming in to inspect a specific city (e.g. Medan at zoom 9+), aircraft hundreds of kilometers away (e.g. in Langsa or Payakumbuh) are outside the camera view frustum. Deck.gl automatically culls off-screen paths.
2. **Metric vs Screen Scale**: A 41.6 km vector is ~20px on zoom 5, but over 1,000px on zoom 11, stretching past the edge of the monitor.
3. **Dead-Reckoning Drift**: Aircraft dead-reckon North at 1,300 km/h (speedScale 2.5 * 520 km/h), quickly moving out of the regional bounding box and looping.

## 4. Issue 3: Main-Thread CPU & GC Latency Bottleneck

### Profile Findings:
1. **60 FPS Non-Stop Layer Re-Allocation**:
   - `animate` in `FleetVehicleLayer.tsx` runs inside `requestAnimationFrame` continuously.
   - Every 16ms, it recalculates dead reckoning for all vehicles, runs `map.project()` on CPU for every vehicle, runs `arbitrateVisibleLabels` (array sorting, bit packing, hash map lookups), creates **5 new Deck.gl Layer instances** (`new PathLayer`, `new ScatterplotLayer`, `new IconLayer`, `new TextLayer`), and calls `overlay.setProps({ layers: deckLayers })`.
   - Result: **300 layer allocations per second**, generating severe Garbage Collection pauses and WebGL buffer thrashing.
2. **Uncoupled Static Arbitration**:
   - When the map is stationary (user is not dragging or zooming), label visibility does not change from frame to frame. Arbitrating labels 60 times a second on a stationary map is 100% redundant CPU waste.
3. **Network Polling Churn**:
   - DevTools console logged 19 CORS & 404 errors firing in parallel on initial dashboard load towards dormant Render backend endpoints without exponential backoff.

### Performance Target:
- Throttle telemetry animation to 25 FPS (40ms tick), saving 60% of animation CPU cycles.
- Run `SpatialHash` arbitration only on camera movement (`move`/`zoom`) or when vehicle positions change significantly (> 15px screen delta), NOT on every animation frame.
- Preserve 60 FPS buttery-smooth pan/zoom for Mapbox native tiles and UI controls while dropping idle CPU usage from ~85% to < 15%.
