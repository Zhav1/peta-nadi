# Phase 81 / Plan 01 — Dispatcher Tenant Fleet Scope: No Mock Routes, No Estimated Corridors

**Goal:** a `DISPATCHER` session must see **only its own tenant's assets**, and only **real `LIVE_GPS` units on the map**. The macro corridor fleet, the client `FALLBACK_FLEET`, and `ROUTE_ESTIMATED` orange corridor projections must never appear as ambient dispatcher telemetry. A projected unit may be inspected deliberately — with a `PROYEKSI` badge — but never drawn as if it were a live truck. `REGULATOR` keeps the macro situational view.

**Scope:** `frontend/lib/fleetScope.ts` (new), `frontend/components/fleet/TenantFleetRoster.tsx` (new), `frontend/hooks/useFleetVehicles.ts`, `frontend/components/map/FleetVehicleLayer.tsx`, `frontend/components/map/CrisisMap.tsx`, `frontend/components/dashboard/DashboardClient.tsx`, `frontend/lib/api.ts`, `frontend/lib/types.ts`, `backend/app/routers/vehicles_router.py`, `backend/app/routers/fleet_ingest_router.py`, `backend/app/services/telemetry_service.py`, `backend/app/db/local_storage.py`, regression tests, `frontend/scripts/test_fleet_scope.ts` (new).

## 2. Observed failure chain (pre-fix)

| # | Layer | Pre-fix behavior | Why it looked wrong to a dispatcher |
|---|---|---|---|
| 1 | Query vs claim | `vehicles_router.py` set `effective_company = company_id` and only fell back to the JWT claim when the query was empty | A dispatcher could widen their own view with `?company_id=jne_sumut`, or be narrowed by any caller that supplied a different id |
| 2 | Backend tenant filter | `get_unified_fleet` kept every `maritime` / `air` unit regardless of tenant: `v.get("modality") in ("maritime", "air") or …` | Even a correctly scoped dispatcher still received macro vessels and flights — the "tenant" view was never actually tenant-only |
| 3 | Client fallback | `baseVehicles = rawVehicles.length > 0 ? rawVehicles : FALLBACK_FLEET` | An honest empty tenant response (or a 500) became the 26-unit client mock fleet. The operator saw trucks that do not belong to them and cannot be dispatched |
| 4 | Estimated corridors | `FleetVehicleLayer` always collected every `ROUTE_ESTIMATED` path and pushed it into `PathLayer` `deck-fleet-estimated-routes` (amber `[245, 158, 11, 150]`, 2.5 px) plus an amber pulse ring | Orange lines crossed the island with no dispatcher ownership and no live GPS. They read as live trucks on a bad signal |
| 5 | Onboarding persistence | `company_id`, `tracking_mode`, `departure_time`, and origin/destination coords lived only in `TelemetryService` memory / `_custom_vehicles_extra`; `custom_fleet_vehicles` had no such columns | A Render cold start would drop the tenant tag, so a freshly onboarded truck could no longer be resolved as belonging to its owner |
| 6 | Response validation | A custom row with no route had `path: null`, but `FleetVehicleTelemetry.path` is `List[List[float]]` (required, non-null) | One incomplete row failed validation for the **entire** `/fleet/vehicles` response → 500 → the client fell back to mocks (#3) |
| 7 | Cache across roles | The 90 s `vehicleCacheRef` was not cleared when `effectiveCompanyId` or role changed | Switching REGULATOR → DISPATCHER could keep displaying the regulator's macro assets until TTL expiry |
| 8 | Retry identity | The direct retry in `fetchFleetWithFallback` hardcoded `https://peta-nadi.onrender.com` and sent **no** `Authorization` header | The retry bypassed the canonical `getBaseUrl()` resolver and carried no JWT claim. Once the backend ignores `?company_id=` for dispatchers, an unauthenticated retry is a guest request: it can return the macro view or fail CORS/404 |

**Diagnosis:** #1–#2 are server-side scope holes; #3–#4 are client-side presentation leaks; #5–#6 are persistence/validation defects that *trigger* #3; #7–#8 let scope decay after the first request. Fixing only the hook still leaves the backend macro filter; fixing only the backend still leaves mock fallback and orange corridors.

**On the "45-unit fallback":** the backend baseline is `MASTER_FLEET_DEFINITIONS`, commented *"Master 45-unit Pan-Sumatra strategic multi-modal telemetry baseline"* (`telemetry_service.py:238`). The client `FALLBACK_FLEET` (`useFleetVehicles.ts:11`) contains **26 hardcoded units**, 5 of them `ROUTE_ESTIMATED`. Both are legitimate macro/demo data; neither is a valid dispatcher answer.

## 3. Non-negotiable constraints

1. **A dispatcher never sees macro or fallback.** No tenant claim → honest empty, never `FALLBACK_FLEET`, never `MASTER_FLEET_DEFINITIONS`, never another tenant's assets.
2. **The JWT claim wins over the query.** `?company_id=` is a regulator/guest introspection filter; it can never widen a dispatcher boundary.
3. **A regulator keeps the macro view.** The fix must not turn the regulator console into a tenant console.
4. **`PROYEKSI` is inspection-only.** `ROUTE_ESTIMATED` units stay discoverable in the roster, but the map draws them only when selected, and always with a `PROYEKSI` badge.
5. **Empty is a valid answer.** An empty tenant fleet renders an explicit empty state with an onboarding action — not a mock fill.
6. **No deployment or commit in this phase.** The code stays in the working tree; the live pair still runs pre-fix code.

The server tag is trusted first because it is derived from the validated JWT claim; `company_id` is retained as a compatibility fallback for older payloads.

### 4.2 Hook scoping — `frontend/hooks/useFleetVehicles.ts`

- **Role split (352–358):** `isDispatcher = role === 'DISPATCHER'`; `effectiveCompanyId` is the claim only for dispatchers; `isTenantScoped` records whether a claim exists.
- **Cache invalidation (372–374):** `vehicleCacheRef.current.clear()` runs whenever `effectiveCompanyId` or `isDispatcher` changes, so a role/tenant switch cannot inherit the previous view.
- **Tenant slice (488–507):** dispatchers use `selectTenantVehicles(rawVehicles, effectiveCompanyId)`; every other role keeps `rawVehicles`.
- **No fallback for dispatchers (503–507):** `baseVehicles = isDispatcher ? tenantVehicles : rawVehicles.length > 0 ? rawVehicles : FALLBACK_FLEET`. A dispatcher's empty list stays empty.
- **Map slice (498, 521–525):** dispatcher `vehicles` is `liveTenantVehicles` only. `estimatedTenantVehicles` is returned separately for the roster/inspector.
- **Toggle removal (535–546):** `isSimulationMode` is forced `false` and `canToggleSimulation` is `false` for dispatchers; `DashboardClient` renders a `Tenant Live GPS (n)` badge instead of the AIS/estimated toggle.
- **Retry keeps identity (313–345):** the direct retry uses `${getBaseUrl()}/api/v1/fleet/vehicles${qs}` and forwards `Authorization: Bearer <token>` from `getAuthToken()`. It also keeps the same `company_id` query as the primary request.

### 4.3 Map layer — `frontend/components/map/FleetVehicleLayer.tsx`

- New `hideEstimatedRoutes?: boolean` prop (49), default `false` (256), threaded from `CrisisMap` (99, 262, 2015).

### 4.5 Backend authorization — `backend/app/routers/vehicles_router.py`

- `is_dispatcher` is computed from the validated session (41).
- For dispatchers, `effective_company = user.company_id` and `tenant_only = True`; **the query parameter is ignored** (43–49).
- Dispatcher with no claim → `200` with `vehicles: []`, zeroed `modality_counts`, and a warning log (51–62). No first/last fallback, no macro fill.
- Regulator/guest keep `effective_company = company_id` and `tenant_only = False` (47–49), so `?company_id=` still narrows introspection.
- `is_tenant_asset` is stamped from `matches_tenant(...)` (80–84).

`fleet_ingest_router.py`:
- `/fleet/register` writes `company_id = user.company_id or user.org_name` and `company_name = user.org_name` onto the saved row (123–127), so a tenant asset is never tenant-less.
- `/fleet/custom` applies the same rule: a dispatcher's `scoped_company` is the claim and a missing claim returns `[]`; regulator/guest may pass `?company_id=` (287–300).

### 4.6 Service + persistence — `telemetry_service.py`, `local_storage.py`

- **`matches_tenant` (1067):** claim matches `company_id` or `organization_id`; the human-readable `org_name` fallback applies **only** to legacy rows whose `company_id` is missing or equal to `organization_id`. An explicit different claim can never be claimed by name.
- **`tenant_only` (1800, 2025–2031):** when true, return only `matches_tenant` units — maritime/air no longer bypass the filter. When false, the old macro behavior is preserved for regulators.
- **Persistence (local_storage.py 115–156):** `custom_fleet_vehicles` gains `company_id`, `company_name`, `tracking_mode` (default `ROUTE_ESTIMATED`), `departure_time`, `origin_coords_json`, `dest_coords_json`; `ALTER TABLE` migrations cover existing databases. `save_custom_vehicle` (605–610) never stores a tenant-less row, and `_row_to_custom_vehicle_dict` (805) backfills `company_id` from `organization_id` for legacy rows.
- **Missing path (1673–1677):** `_enrich_custom_vehicle` writes `item["path"] = []` whenever the key is `None`. `FleetVehicleTelemetry.path` is required and non-null, so this prevents one un-routed row from failing the entire list response with a 500.
- **Registry (818–839):** `list_custom_vehicles(company_id=...)` filters `(company_id = ? OR organization_id = ?)`. Master truck assets (`truck_assets`) are synthesized as `ROUTE_ESTIMATED` tenant units (telemetry_service 1800+) so an asset without a GPS fix still appears in the owner's roster.

## 7. Risks / trade-offs

- **Projected units become less visible by default.** That is intentional: an estimated corridor is not a live truck. The roster is the discoverability surface, and inspection restores the line. If dispatchers expect to see all planned routes at once, this will feel like missing data on first use.
- **One malformed row still has fleet-wide blast radius.** The `path: []` guard removes the known trigger, but any other required field (`vehicle_id`, `speed_kmh`, coordinate ranges) can still fail the whole list response. Row-level serialization would be the durable fix.
- **Cache clearing is not request cancellation.** `fetchFleet` has no `isMounted` guard; an in-flight request started under the previous role/token can resolve after the clear and write into `rawVehicles`. Server-side scoping makes it return the *old* token's tenant, not a widened view, but a brief cross-tenant flash is still possible on a slow connection.
- **Legacy org-name matching is a heuristic.** `matches_tenant` falls back to `org_name` only when `company_id` is absent or equal to `organization_id`; two legacy tenants sharing an org display name could still collide. New rows always store the claim, so the exposure shrinks over time.
- **Regulators still get `FALLBACK_FLEET` on an empty response.** That is deliberate macro resilience, and it is why the fallback must remain role-gated rather than removed globally.
- **A `PROYEKSI` unit with no route has an empty `path`.** It is listed but cannot be framed on the map; onboarding still needs a travel or origin/destination pair to give it geometry.
- **Live deployment is untested.** The working tree also carries Phase 44/ERP and Phase 80 changes; the tenant fix should be deployed and probed as its own commit before the acceptance table is called production-verified.
