### WP1: Two-Layer State Architecture & WebSocket Isolation Guard (`frontend/components/dashboard/DashboardClient.tsx`)
1. **State Categorization & Demarcation:**
   - **Layer 1 (Global Shared State - Read-Only Broadcast):**
     * `incidents`, `spatialWeatherPolygons`, `combinedDisasterZones`, `newsFeed`, `activeFleetVehicles`.
     * Receives broadcast environmental ground truth.
   - **Layer 2 (Session-Local State - Scoped to Current Browser Tab):**
     * `selectedOriginNode`, `selectedDestNode`, `selectedModality`, `activeRouteIdx`, `currentMapRoutes`, `simulatedShockwave`, `selectedRadius`.
     * Scoped strictly to the active user's viewport.
2. **WebSocket Message Isolation Guard:**
   - In `handleWsMessage(event: WsEvent)`:
     * When receiving `node_update` from `/ws/crisis/{id}`, strip `route_recommendations` and route polyline data from the ambient event before updating `selectedCrisis`.
     * Ambient incident telemetry must NEVER overwrite or re-color the user's active session routes (`currentMapRoutes`).

### WP2: Bidirectional URL Query Parameter Synchronization (`frontend/components/dashboard/DashboardClient.tsx`, `frontend/app/dashboard/page.tsx`)
1. **Next.js Suspense Boundary (`frontend/app/dashboard/page.tsx`):**
   - Wrap `<DashboardClient />` with `<Suspense fallback={...}>` in `app/dashboard/page.tsx` conforming to Next.js 14 App Router standards for `useSearchParams()`.
2. **Initial State Hydration (`DashboardClient.tsx`):**
   - Read URL search parameters on component mount:
     * `origin`: Initializes `selectedOriginNode` (e.g. `'belawan'`).
     * `dest`: Initializes `selectedDestNode` (e.g. `'tebingtinggi'`).
     * `modality`: Initializes `selectedModality` (e.g. `'truck' | 'maritime' | 'air' | 'multimodal' | 'best'`).
     * `route`: Initializes `activeRouteIdx` (e.g. `0 | 1 | 2`).
     * `crisis`: Initializes `selectedCrisisId`.
3. **Synchronous URL State Mirroring:**
   - Implement `updateUrlParams(updates: Record<string, string | null>)` utilizing `window.history.replaceState` to mutate the URL query string in-place without triggering full Next.js page remounts or visual flicker.
   - Mirror updates when:
     * Origin node changes $\rightarrow$ `updateUrlParams({ origin: newOriginId })`
     * Destination node changes $\rightarrow$ `updateUrlParams({ dest: newDestId })`
     * Modality tab changes $\rightarrow$ `updateUrlParams({ modality: newModality })`
     * Route card / polyline clicked $\rightarrow$ `updateUrlParams({ route: String(newRouteIdx) })`
     * Clean slate reset $\rightarrow$ `updateUrlParams({ origin: null, dest: null, route: null, crisis: null })`
