# Plan 42-01: Backend Supabase JWT Auth Middleware, Role-Based Access Control (RBAC), User Routers & Pytest Suite

## 1. Goal & Objectives
Implement a robust, production-grade Supabase JWT authentication and Role-Based Access Control (RBAC) layer for the FastAPI backend. Support three primary personas (`DISPATCHER`, `REGULATOR`, `GUEST`), provide deterministic offline session fallbacks for competition evaluation, protect critical endpoints (e.g. route approvals), and verify full test coverage with automated pytest suites.

---

## 2. Proposed Changes & File Modifications

### Task 1: Supabase JWT Middleware & RBAC Dependency
- **File**: `backend/app/auth/supabase_auth.py` (New)
- **Changes**:
  - Implement token decoder supporting HS256 / RS256 with Supabase `JWT_SECRET` and JWKS caching.
  - Implement secure role extraction from `app_metadata.role` (per Supabase security standards).
  - Define role permission maps:
    * `DISPATCHER`: `["fleet:read", "fleet:write", "routes:plan", "approvals:write", "manifests:upload"]`
    * `REGULATOR`: `["heatmap:read", "prices:read", "reports:read", "reports:export", "audit:read"]`
    * `GUEST`: `["all:sandbox", "benchmark:read", "scenarios:run", "simulation:write", "approvals:write"]`
  - Implement FastAPI dependencies:
    * `get_current_user`: extracts and validates bearer token, returns `UserSession`.
    * `get_optional_user`: returns authenticated `UserSession` if token present, or default guest session if absent.
    * `require_roles(allowed_roles: list[str])`: dependency enforcing role membership, raising HTTP 403 Forbidden on violation.
  - Implement offline token generator `create_guest_token(role, org_name, email)` for seamless local testing.

### Task 2: Auth Router & Identity Endpoints
- **File**: `backend/app/routers/auth_router.py` (New)
- **Changes**:
  - Define Pydantic models: `UserSession`, `GuestSessionRequest`, `GuestSessionResponse`, `RoleSwitchRequest`, `RoleInfo`.
  - Implement `GET /api/v1/auth/me`: Returns current user metadata, role, organization, and permissions.
  - Implement `POST /api/v1/auth/guest-session`: Generates signed JWT for specified role (`DISPATCHER`, `REGULATOR`, `GUEST`) with default organization names.
  - Implement `POST /api/v1/auth/switch-role`: Instant 1-click persona switch for evaluators.
  - Implement `GET /api/v1/auth/roles`: Returns list of available operational roles and descriptions.

### Task 3: Endpoint Protection & FastAPI Integration
- **Files**: `backend/app/main.py`, `backend/app/routers/approvals.py`
- **Changes**:
  - `main.py`: Include `auth_router.router` under prefix `/api/v1/auth`.
  - `approvals.py`: Update `POST /api/v1/approvals` to use `require_roles(["DISPATCHER", "GUEST"])`. When a `REGULATOR` tries to submit an approval, return HTTP 403 with message: "Akses ditolak: Hanya operator berwewenang (DISPATCHER) yang dapat menyetujui pengalihan rute armada."

### Task 4: Automated Test Coverage
- **File**: `backend/tests/test_auth_rbac.py` (New)
- **Changes**:
  - Test valid JWT decoding and user claims extraction.
  - Test invalid / malformed / expired token rejection (HTTP 401).
  - Test role-based access control:
    * `DISPATCHER` can create approvals (HTTP 200).
    * `REGULATOR` is forbidden from creating approvals (HTTP 403).
    * `GUEST` can create approvals in sandbox mode (HTTP 200).
  - Test guest session creation for all 3 personas.
  - Test role switching endpoint.
  - Verify all tests pass cleanly in pytest.
