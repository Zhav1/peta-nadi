# Plan 39-01: Multi-Modal Telemetry Ingestion, Transponder Schemas & Automated Test Harness

<objective>
Implement the multi-modal transponder telemetry ingestion engine and schema contracts for PreHub's logistics fleet across Sumatra. Provide maritime AIS (MMSI, IMO, SOG, COG), air cargo ADS-B (ICAO24, Callsign, Altitude), and arterial highway truck GPS with IoT cold-chain temperature monitoring (<= 4.0°C threshold). Ensure resilient offline cache fallback and full frontend TypeScript type parity.

Purpose: Ground PreHub's operational situational awareness in real-world transponder protocols with high availability and deterministic offline operation.
Output: Pydantic v2 schemas, TelemetryService with 60s OpenSky caching and Redis AISstream integration, enriched vehicles router, Pytest test suite, and synchronized frontend types.
</objective>

       - Maintain `_opensky_cache: Dict[str, Any]` and `_opensky_cache_ts: float`.

       - For the 24 highway logistics trucks, compute route bearing (`heading_deg`).
       - Assign realistic IoT temperature telemetry (`temperature_c`) for cold-chain cargo:
         - Perishable units (produce/meat/pharma e.g. `TRK-002`, `TRK-008`, `TRK-014`, `TRK-016`, and `AIR-001`) have temperatures between 2.2°C and 3.8°C (status `NORMAL`).
         - Support excursion simulation parameter: any temperature > 4.0°C is automatically tagged as `ColdChainStatus.WARNING_EXCURSION`.
       - Assign transponder attributes: `vin` (e.g. `MHF12TRK001PLM`), `signal_status = SignalStatus.SIMULATION_CACHE`, `telemetry_source = "CORRIDOR_GPS"`.
    5. Expose `get_unified_fleet(modality: Optional[str] = None, status: Optional[str] = None) -> List[Dict[str, Any]]`:
       - Combines all 45 fleet units across all modalities.
       - Applies `modality` and `status` query filters.
       - Calculates `last_ping_seconds_ago` (randomized between 0.8s and 2.4s for live ping heartbeat).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External Feed → Backend Ingestion | Untrusted external network data from OpenSky REST API and AISstream WebSocket enters backend. |
| Client → API Router | Query parameters (`modality`, `status`) cross HTTP boundary into FastAPI router. |
| Backend → Frontend State | Telemetry payload serialized over JSON and consumed by React state hooks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | Denial of Service | `backend/app/services/telemetry_service.py` | mitigate | OpenSky Network REST requests are throttled with a 60-second in-memory cache TTL; client calls never trigger unbuffered external API requests. |
| T-39-02 | Tampering | `backend/app/schemas/fleet.py` | mitigate | Pydantic v2 schemas strictly validate coordinate bounds (-90 to +90, -180 to +180), speed >= 0, and enumerate allowed modality and status values. |
| T-39-03 | Information Disclosure / Outage | `backend/app/routers/vehicles_router.py` | mitigate | Seamless offline fallback to 45 Sumatra baseline units ensures zero HTTP 500 errors and marks signal status as `CACHE_FALLBACK` or `SIMULATION_CACHE`. |
| T-39-SC | Tampering | Package installs | mitigate | Zero new dependencies added. All packages (`fastapi`, `redis`, `httpx`, `pydantic`) verified in repo. |
</threat_model>
