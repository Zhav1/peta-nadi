## Observations / follow-ups
1. **Cache can mask a deploy for up to 1 h.** Any future FIRMS fix should either bump the cache key (`SOURCE_CACHE_PREFIX` + `firms_hotspots:<rev>`) or delete the Redis key on deploy, otherwise verification always waits out `FIRMS_REFRESH_S`. This rollout's empty→140 flip is a true fix signal, but it is indistinguishable from a cache expiry by envelope shape alone; only `updated_at` moving past the deploy time proves the new build served it.
2. Verifying "is the new build live?" should not rely on the FIRMS endpoint during that hour — no `GIT_SHA` / `RENDER_GIT_COMMIT` is exposed by `/health`. Consider adding a build id to `/health`.
3. `/health` still reports `environment:"development"` although `render.yaml` sets `ENVIRONMENT=production` (pre-existing, carried over from R1 note 3).
