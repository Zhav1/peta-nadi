# 🚀 Product Requirements Document (PRD) — UMKM Assistant

## 1. Product Overview
**Name**: UMKM Assistant (Garda-Swadaya V3.0)
**Tagline**: WhatsApp-first intelligent sourcing assistant & export accelerator for UMKM.
**Core Value Proposition**: Turn vague business needs into structured, actionable connections while minimizing friction before transactions happen.

## 2. Problem Statement
Indonesian UMKMs face high friction when finding reliable suppliers (B2B sourcing) and scaling their operations. Additionally, most UMKMs are disconnected from the export ecosystem because they lack readiness insights, certifications, and buyer connections. Existing platforms are transaction-heavy marketplaces that demand high technical literacy and upfront commitment, which creates friction.

## 3. Product Vision & Strategy (Hackathon Winning Angle)
We are building a **conversational bridge**, not another bloated marketplace. 
**Design Principles**:
- **Fast over complex**: WhatsApp-first interactions.
- **Guidance over control**: We facilitate, we do not escrow.
- **Insight over feature quantity**: Actionable export readiness and supplier matching.
- **Pre-transaction value**: Focus on the matchmaking and requirement structuring.

## 4. Key Features & User Stories

### A. Buyer Side (WhatsApp-First)
- **Frictionless Authentication**: No passwords or forms. The system uses the WhatsApp Phone Number as the primary key (`user_id`). Users access the Web Dashboard via session-based **Magic Links** generated by the bot.
- **Progressive Profiling**: The LangGraph engine learns about the business (certifications, industry, location) block-by-block during natural conversation and updates the Postgres profile state automatically.
- **Natural Language Sourcing**: Buyers can type unstructured requests (e.g., "butuh supplier plastik makanan...").
- **Intent Clarification**: The agent asks minimal, focused follow-up questions to structure the requirement.
- **Smart Matchmaking (with Fallback)**: Recommends 3 curated internal suppliers based on MOQ, location, and price. If internal matches are insufficient, it automatically invokes a **Web Search Fallback** to provide curated links from external B2B marketplaces (Tokopedia, Shopee).
- **RFQ Generator**: Auto-generates professional outreach messages for the buyer to send to the supplier.
- **Export Advisor (with Fallback)**: Contextually evaluates export readiness (certifications, buyer types, target markets). Queries live web data if internal RAG lacks specific global market trends.

### B. Buyer Side (Web Dashboard - Deep Experience)
- **Business Snapshot**: Visualizes the UMKM's current state and health.
- **Sourcing History**: Logs past requests and contacted suppliers.
- **Export Advisor (Detailed)**: Comprehensive checklists, certification tracking, and logistics guides.
- **Opportunity Insights**: Proactive demand alerts (e.g., "Growing demand in Malaysia for your product").

### C. Supplier Side (Web Dashboard)
- **Lightweight Registration**: Captures business name, location, category, and minimum viable data.
- **Catalog Management**: Add products with defined MOQ, price, location, and delivery capabilities.
- **System Auto-Tagging**: Dynamically tags suppliers (e.g., "low MOQ", "scalable") to improve match quality.

## 5. Technology Stack (System-First Approach)
*Note: Selected for speed, scalability, and token economy.*

### Core Infrastructure
- **Frontend**: Next.js 14 (App Router) + TailwindCSS + shadcn/ui (Premium, accessible, fast UI).
- **Backend**: Node.js / TypeScript (Fast execution, strong typing).
- **Database**: PostgreSQL (Supabase for rapid development, built-in Auth, and real-time features).
- **Messaging API**: WhatsApp Cloud API / Twilio (For the conversational interface).

### AI & Agent Engine (Optimized for Hackathon & WhatsApp)
- **Framework**: LangGraph (State-machine based deterministic routing for maximum reliability).
- **LLM**: Gemini 1.5/2.0 Flash (Chosen for blazing fast inference speed, massive context window for RAG, and cost-efficiency. Speed is critical for WhatsApp UX).
- **Matching Engine**: Vector Database (pgvector within Supabase) for semantic matching.

## 6. Success Metrics (Hackathon Focus)
- **Friction Reduction**: Time taken from raw intent to sending the first supplier message (< 2 minutes).
- **Match Accuracy**: High relevance of the top 3 recommended suppliers.
- **Actionability**: Number of UMKMs completing the export readiness assessment.

## 7. What We Are Intentionally NOT Building
- Payment processing or escrow systems.
- Complex dispute resolution or fulfillment tracking.
- A full-blown transaction marketplace.
*(This boundary is crucial to demonstrate extreme focus and feasibility for a hackathon).*

## 8. Development Roadmap (Hackathon Timeline)
1. **Phase 1: Agent Core** (WhatsApp webhook, LLM intent extraction, structuring logic).
2. **Phase 2: Supplier DB & Matching** (Seeding supplier data, implementing vector/semantic search).
3. **Phase 3: Web Dashboard** (Buyer summary, export roadmap, supplier catalog).
4. **Phase 4: Polish** (UX micro-animations, premium aesthetic implementation).
