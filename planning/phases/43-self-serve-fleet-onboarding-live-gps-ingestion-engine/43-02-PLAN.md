# Plan 43-02: Frontend Fleet Onboarding Modal, CSV Parser, Webhook Simulator & WebGL Dynamic Sync

**Phase:** 43
**Plan:** 43-02
**Goal:** Build the frontend Self-Serve Fleet Onboarding Modal (`FleetOnboardingModal.tsx`), integrate client-side CSV parsing with downloadable templates, provide an interactive TMS Webhook test simulator, and wire dynamic WebGL fleet synchronization on the 4D Map canvas.

---

## 1. Requirements & Invariants

- **UI-UX Design System Compliance**:
  - Dark glassmorphism (`backdrop-blur-xl bg-[#0c0e12]/95 border border-white/10 rounded-2xl shadow-2xl text-slate-100`).
  - 100% monochrome Lucide SVG icons (Zero emojis).
  - Explicit `cursor-pointer` on all interactive buttons and triggers.
  - Smooth micro-interactions and transitions (150ms–300ms).
- **Role-Adaptive Trigger**:
  - `[ + Onboard Armada ]` header action button in `DashboardClient.tsx`.
  - Accessible to `DISPATCHER` and `GUEST`; informative advisory modal for `REGULATOR`.
- **Dynamic Mapbox WebGL Sync**:
  - Onboarded vehicles instantly appear in `FleetVehicleLayer.tsx` with smooth 60 FPS animation, bearing vectors, and targeting crosshairs.

---

## 2. Technical Scope & Implementation Steps

### Task 1: TypeScript Types & API Client Integration
- Update `frontend/lib/types.ts`:
  - Add `CustomVehicleRegisterPayload`, `TMSWebhookPingPayload`, `ManifestTemplateInfo`.
- Update `frontend/lib/api.ts`:
  - `api.fleet.register(data)`
  - `api.fleet.uploadManifest(data)`
  - `api.fleet.ingestTelemetry(ping)`
  - `api.fleet.listCustom()`
  - `api.fleet.deleteCustom(vehicleId)`
  - `api.fleet.getManifestTemplate()`
  - `api.fleet.simulatePing(vehicleId, payload)`

### Task 2: Fleet Vehicles Hook Enhancements (`frontend/hooks/useFleetVehicles.ts`)
- Add `refetch()` method to `useFleetVehicles`.
- Expose `customCount` and optimistic append capabilities so newly registered vehicles appear without delay.

### Task 3: Self-Serve Fleet Onboarding Modal (`frontend/components/fleet/FleetOnboardingModal.tsx`)
- Build glassmorphic modal with 3 functional tabs:
  1. **Tab 1: Pendaftaran Manual (Single Asset)**:
     - Form fields:
       - Nomor Polisi / Asset ID (e.g. `BK-9182-TK`)
       - Nama Armada / Identitas Unit (e.g. `Truk Cold-Chain Sayur Berastagi #4`)
       - Kontak Pengemudi / Sopir (e.g. `+6281234567890`)
       - Moda Transportasi (Radio / Selector: Truk Darat, Kapal Laut, Pesawat Udara)
       - Komoditas & Muatan (e.g. `12 Ton Cabai & Sayur Segar`)
       - Suhu Pendingin / Cold-Chain (°C) (e.g. `2.5`)
       - Hub Asal & Hub Tujuan (Dropdown of known Sumatra strategic hubs: Belawan, Medan, Binjai, Tebing Tinggi, Siantar, Kabanjahe, Bakauheni, Palembang, etc.)
       - Kecepatan Operasional (km/j)
     - Real-time path preview & coordinate synthesis.
     - Submit handler with loading state and error handling.
  2. **Tab 2: Unggah Massal Manifest (CSV / Excel)**:
     - File dropzone with `.csv` file support.
     - "Unduh Template CSV" button that generates/downloads a compliant template.
     - Client-side parser parsing CSV rows and displaying an interactive preview table with validation status badges (`VALID` / `PERINGATAN`).
     - "Impor X Armada" action button triggering `POST /api/v1/fleet/upload-manifest`.
  3. **Tab 3: Integrasi Webhook TMS / GPS Live**:
     - Webhook endpoint URL display with 1-click copy button (`POST /api/v1/fleet/telemetry/ingest`).
     - TMS compatibility guide (Traccar, EasyGo, McEasy JSON payload structure).
     - **"Simulator Test Ping GPS"**:
       - Dropdown to pick an active vehicle or input a custom ID.
       - Latitude / Longitude / Speed / Temperature sliders or inputs.
       - "Kirim Ping Telemetri" button that sends live ping and updates the asset on the live map.

### Task 4: Dashboard Integration & Dynamic Map Retargeting (`frontend/components/dashboard/DashboardClient.tsx`)
- Add `[ + Onboard Armada ]` button to the top header navbar next to time filters / telemetry.
- Show active onboarded count badge if > 0.
- When a new vehicle is registered or a ping simulated, invoke `refetch()` and optionally fly camera to vehicle coordinates.

### Task 5: Production Build Verification
- Execute `npm run build` in `frontend/` to confirm 0 TypeScript and lint errors.
