# Plan 42-02: Frontend Supabase Client, Auth Context, Minimalist Auth Modal & Role-Adaptive Navigation

## 1. Goal & Objectives
Deliver the frontend authentication layer and multi-persona workspace management in Next.js. Implement Supabase client integration with offline fallback, a global React Auth Context with 1-click persona switching for competition evaluators, a strict zero-emoji glassmorphic Auth Modal, and role-adaptive top navigation and action button gating.

---

## 2. Proposed Changes & File Modifications

### Task 1: Supabase Client & API Client Auth Header Integration
- **Files**: `frontend/lib/supabaseClient.ts` (New), `frontend/lib/api.ts` (Modify)
- **Changes**:
  - `supabaseClient.ts`: Initialize `@supabase/supabase-js` client using `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Provide safe offline fallback if credentials are absent.
  - `api.ts`:
    - Add `setAuthToken(token: string | null)` to store active session token.
    - Inject `Authorization: Bearer <token>` in `request()` headers when token is set.
    - Add `api.auth` methods: `me()`, `createGuestSession(role, orgName)`, `switchRole(role)`, `roles()`.

### Task 2: Global Auth Context & State Management
- **File**: `frontend/lib/authContext.tsx` (New)
- **Changes**:
  - Define `UserRole = 'DISPATCHER' | 'REGULATOR' | 'GUEST'`.
  - Define `UserProfile` interface: `{ id, email, role, orgName, name, permissions }`.
  - Create `AuthContext` and `AuthProvider` providing:
    * `user`: active user profile.
    * `token`: active JWT or offline mock token.
    * `role`: active role.
    * `isLoading`: boolean.
    * `isAuthenticated`: boolean.
    * `isAuthModalOpen`: boolean.
    * `openAuthModal()` / `closeAuthModal()`.
    * `switchRole(role)`: instant persona switcher calling backend guest-session and updating local state.
    * `login(email, password)`: Supabase auth.
    * `loginWithMagicLink(email)`: Supabase passwordless OTP.
    * `logout()`: Revert to Guest evaluator persona.
  - Persist session in `localStorage` with automatic rehydration on mount.

### Task 3: Minimalist Glassmorphic Auth Modal
- **File**: `frontend/components/auth/AuthModal.tsx` (New)
- **Changes**:
  - High-contrast glassmorphic dialog: `backdrop-blur-2xl bg-[#0c0e12]/95 border border-white/10`.
  - Zero emojis (100% monochrome Lucide SVG icons: `User`, `Shield`, `Key`, `Mail`, `ArrowRight`, `Lock`, `Building`, `CheckCircle2`, `Sparkles`, `X`, `Briefcase`, `Scale`, `FlaskConical`).
  - 3 Navigation Tabs:
    1. **"1-Klik Persona (Evaluator)"**:
       - 3 interactive cards with hover glow and instant switch:
         * **Dispatcher Logistik** (`PT Samudera Logistik Sumatra`): Focus on routing, fleet coordination, and reroute approvals.
         * **Regulator Pemerintah** (`Badan Pangan Nasional / Kemenhub`): Focus on macro vulnerability, PIHPS price heatmaps, and executive reports.
         * **Guest Evaluator** (`Kompetisi LRIP Sandbox`): Unrestricted sandbox and benchmark evaluation.
    2. **"Email & Sandi"**: Supabase email + password form for production login/register.
    3. **"Magic Link"**: Supabase passwordless login form.

### Task 4: Role-Adaptive Top Navigation & UI Gating
- **Files**:
  - `frontend/components/dashboard/DashboardClient.tsx` (Modify)
  - `frontend/components/sidebar/MitigationTab.tsx` (Modify)
  - `frontend/app/layout.tsx` (Modify)
- **Changes**:
  - `layout.tsx`: Wrap application with `<AuthProvider>`.
  - `DashboardClient.tsx`:
    - Top header right: Add Role Badge / Persona Pill button (`[ DISPATCHER ] PT Samudera`, `[ REGULATOR ] Bapanas`, `[ GUEST ] Evaluator`) with role-specific color tint and active dot.
    - Clicking pill triggers `openAuthModal()`.
    - Embed `<AuthModal />` in dashboard canvas.
    - Adapt navigation tab visibility and visual hierarchy based on role:
      * `DISPATCHER`: Highlight `PETA OPERASI`, `SIMULATION`, `EVALUATION`.
      * `REGULATOR`: Highlight `PETA OPERASI`, `ANALYTICS`, `REPORTS`, `EVALUATION`.
      * `GUEST`: Highlight all tabs.
  - `MitigationTab.tsx`:
    - Access active `role` from `useAuth()`.
    - If role is `REGULATOR`, render a read-only advisory pill: `HANYA DISPATCHER BERWENANG MENYETUJUI RUTE` (button disabled).
    - If role is `DISPATCHER` or `GUEST`, render active `[ SETUJUI & DISPATCH PENGALIHAN ]` button.
